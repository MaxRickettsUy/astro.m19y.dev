# AGENTS.md

Guidance for coding agents working in this repository.

## Project Overview

This is the personal site for `m19y.dev`: links, projects, collections, and yearly read/watch/listen logs.

The site is built with Astro 6 and Tailwind CSS 4, and is deployed on Netlify. Most pages are static Astro files, with some collection pages loading data from JSON files in `public/`.

## Commands

- `npm install` - install dependencies.
- `npm run dev` - start the Astro dev server, usually at `localhost:4321`.
- `npm run build` - build the production site to `dist/`.
- `npm run preview` - preview the production build locally.
- `npm run astro -- <cmd>` - run Astro CLI commands, for example `npm run astro -- check`.

There are no dedicated test, lint, or type-check scripts. Use `npm run build` for the main verification pass, and `npm run astro -- check` for ad-hoc Astro/TypeScript diagnostics.

## Repository Layout

- `src/pages/` - file-based Astro routes.
- `src/layouts/Layout.astro` - shared document layout, metadata, header, footer, view transitions, analytics, and global style import.
- `src/components/` - shared Astro components.
- `src/styles/global.css` - Tailwind import and global/shared styles.
- `src/img/` - source-controlled image assets imported by Astro.
- `public/` - static assets, JSON content files, favicons, and larger image files.
- `docs/` - reference documents.
- `plans/` - planning notes; do not treat these as site content.
- `dist/` - generated production output; do not edit by hand.

## Routing And Content

Astro file-based routing maps `src/pages/foo/bar.astro` to `/foo/bar`.

Top-level routes include:

- `src/pages/index.astro` - home page.
- `src/pages/uses.astro` - uses page.
- `src/pages/random/` - collections such as cool sites, garden, merch, wine night, camp wood, and beans.
- `src/pages/rwl/` - read/watch/listen pages by year.

Collection pages often import JSON from `public/` and render it with `.map()`. When adding or updating entries in those collections, prefer editing the matching JSON data file instead of hardcoding new repeated content in the Astro template.

Some existing hand-written links may include legacy `.html` suffixes or omit them. Check nearby links before changing URL style in a section.

## Imports And Assets

Prefer the configured TypeScript path aliases over long relative imports:

- `@components/*` -> `src/components/*`
- `@layouts/*` -> `src/layouts/*`
- `@img/*` -> `src/img/*`
- `@styles/*` -> `src/styles/*`
- `@public/*` -> `public/*`

Use Astro's `astro:assets` `<Image />` component for imported page-level assets from `src/img/` when practical. Files in `public/` should be referenced by absolute site paths such as `/avatar.png`.

## Styling Conventions

Tailwind utilities are used heavily in Astro templates. Global and shared CSS belongs in `src/styles/global.css`.

Keep styling changes small and consistent with the current personal-site feel. Avoid broad rewrites of layout, typography, or color unless the task specifically asks for a redesign.

## Versioning

`package.json` uses calendar versioning in the form `YYYY.M.D`. The site links the current package version to the matching GitHub release tag.

When bumping the version, also add a matching `CHANGELOG.md` entry under a new `## [YYYY.M.D]` heading. A release tag with the same version is expected for published releases.

## Working Rules

- Do not edit `dist/` directly; it is generated by `npm run build`.
- Do not move or rewrite existing content unless the task calls for it.
- Preserve unrelated user changes in the working tree.
- Prefer focused changes over sweeping refactors.
- Run `npm run build` before finishing changes that affect site behavior, routing, imports, or styling.
